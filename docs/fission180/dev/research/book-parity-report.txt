  Fission 180 vs Fusion — Book Parity Report
     Nov 10, 2026        ·   ​@Luca Sciabica




  Summary
  A Fusion user can follow the book's modelling chapters (1–6 and 9) in Fission 180, but each
  project hits several rough edges. Chapters 7, 8, 10 and 11 fail at their core because the
  Render, Animation and Manufacture workspaces don't exist.

  I ran Fission 180 0.1.0-beta.3.3.9 (Linux AppImage, FreeCAD 1.1.4 core) with real mouse and
  keyboard input. I worked through Mastering Autodesk Fusion, 2nd ed. chapter by chapter
  and logged every step as one of the outcomes in the table below.

     OK                         Worked the way the book says                        198

                                hiccup

     Workaround                 The book's way failed and another way worked (the   63
                                steps are logged)

     Fail                       Could not be done in Fission                        44

     Not tested                 Skipped for time or missing downloads               15


  Coverage: I did chapters 1–5 step by step, from The Basics through the Pizza Cutter. For
  the Tesla Turbine I built the housing to the book's dimensions, then tested every new tool
  on simplified parts. For chapters 6–12 I tested each chapter's new tools on small stand-in
  models rather than rebuilding every part.

  What works well: sketching and constraints, Extrude/Revolve/Loft/Sweep/Coil, Thread
  and Hole, feature and body patterns, Split Body, Combine and Midplane. Joints, Motion
  Link, Motion Study and Rigid Group work too. Highlights are the Gear tool, the Drawing
  workspace (views, section, detail, dimensions, parts list with balloons, PDF export),
  Canvas with Calibrate, and Decals.

  Weakest areas:

     1. Work across components: geometry lands in the wrong component, and you can't
          project from or snap to another component.
     2. Joint editing: edits to as-built joints are silently lost, and joint references go stale.
     3. Parameters: the "+" button is broken.
     4. Appearances: flat colours only.
     5. Silent failures: many commands simply do nothing, with no message.


  Bugs to fix first
  These reproducibly do the wrong thing. They are grouped by area, and the worst of each
  group comes first. "Seen in" names the book project where I hit it.


  Parameters and units
     1. Parameters "+" button does nothing. MODIFY > Change Parameters > "+" only shows
        'bool' object has no attribute 'strip' in red. Cause: in parameters_ui.py ,
           add_button.clicked.connect(self.add_parameter) passes Qt's checked=False in
          as the parameter name. Fix: connect to lambda: self.add_parameter() . The + and −
          buttons are also drawn as blank white squares. Typing Head_Diam = 8.5 in a
          dimension box doesn't create a parameter either, so there is no in-app way to make a
          user parameter. Seen in: Metric Bolt.
     2. Design units silently go back to mm. Set the design to Inch, then press Ctrl+Z on any
        step: Document Settings shows mm again and every dialog takes mm. Ctrl+Y doesn't
        bring inches back. It also happened without any Undo, after a Change Parameters edit
          and after some Chamfer OKs (5 times in one project). Typing "0.02" then means 0.02
          mm. Seen in: Fire Piston.
     3. Deleting a sketch constraint mis-wires parameter links. After a delete, the
        expressions on later dimensions don't renumber. Support_Width / 2 jumped onto a
          point-on-object constraint, and another link pointed past the end of the list ("Array
          out of bound: 34, 31"). Any delete in a parametric sketch can silently cut or swap
          parameter links. Undo restores them. Seen in: Drone.
     4. Negative mm parameters become 0. A user parameter in mm is stored as a Length, so
        "−2.5" becomes 0 mm and the extrude that uses it breaks. Workaround: store 2.5 and
        type -Thickness in the distance box. Seen in: Drone.

  Geometry lands in the wrong component
  This is one family: Fission puts new geometry in the component you clicked on, not the
  active component as Fusion does.

     5. A sketch on another component's face switches the active component. With "PTFE
        Tube" active, starting a sketch on the Nozzle's face made the Nozzle active, so the
        sketches and the swept tube went into the Nozzle. Seen in: Hot End.
     6. Extrude of a face with New Body goes into the face's component. With "Housing
        Gaskets" active, extruding the housing's face put the new body in Housing. Seen in:
          Tesla Turbine.
     7. Offset Plane goes into the face's component. An offset plane from a gasket face
        went into the gasket, and so did the sketch and bodies built on it. Seen in: Tesla
        Turbine.
     8. Axis Through Cylinder goes into the cylinder's component. So you can't make the
          book's "component that contains only an axis". Seen in: Robotic Hand.
     9. New Component silently ticks "From Bodies". If steps are still selected in the
        timeline, the selected body is moved into the new component, and the next Revolve
        joins into it. Seen in: Fire Piston.
   10. The first extrude in a new component defaults to Cut. It overlapped a body in
       another component and cut it, silently changing that component. Fusion starts a new
       component's first extrude as New Body. Seen in: Strandbeest.

  For 5–9 the workaround is to right-click the body > Move to Component. This sometimes
  leaves an empty, invalid Body behind.


  Joints
   11. Edit Joint on an as-built joint is lost. Change the Type (e.g. Rigid → Cylindrical) and
          press OK: the change shows, but its transaction stays open
          ( App.getActiveTransaction() = "Edit As-Built Joint"). The next command (Edit
          Joint Limits, Motion Link, even Ctrl+S) aborts it, and the joint goes back to Rigid with
          no Redo. Reproduced 3 times. Seen in: Pizza Cutter.
   12. Edit Joint Limits on an as-built joint shows the wrong dialog. It opens showing Type
          "Rigid" with no limits, and its Cancel also reverts the earlier edit. Seen in: Pizza Cutter.
   13. As-built Slider with no axis silently becomes Rigid. No warning. Seen in: Fire Piston.

   14. Joint references go stale. After later edits the solver reports "Broken link in
       Reference1/2". Element names become ?Face5 / ?Edge41 , and every joint dialog

  Appearances
   16. Looks silently lost. A body shows plain grey while the Appearance panel still lists its
       look, for example after Isolate/Exit Isolate + Move. Dropping the same look again does
          nothing, because appearance.apply() caches the applied look per step.
          Workaround: drop a different look, then the right one again. Seen in: Fire Piston, Pizza
          Cutter.
   17. A face look dropped on an edge colours the whole body. With Apply To = Faces, a
       drop that lands on an edge applies the look to the whole body, and that wipes every
          face look already given. Fusion keeps face looks under a body look. Seen in: Saturn V.


  Timeline, undo and the Gear tool
   18. Undo of Combine leaves an orphan step. An invalid "Combine 1" ("There is no solid in
          the target body") stays in the timeline and must be deleted by hand. Seen in: Drone.
   19. Gear with an invalid fillet makes a copy of the previous gear. The dialog warns that
          the 0.88 mm root fillet doesn't fit (max 0.741), but OK creates a copy of the previous
          gear instead of refusing. Seen in: Gear Train.
   20. Edit Feature on a Gear step deletes it. Right-click a Gear step in the timeline > Edit
          Feature: nothing opens, and the step vanishes along with its body. Seen in: Gear Train.

  Recurring friction patterns
  Most of the 123 friction notes fall into a few patterns. Fixing a pattern once would remove
  many hiccups at the same time. They are ordered by how often a Fusion user would hit
  them.

     1. Silent failures. About 40 log entries say a command did nothing, or did something else,
          with no message. Examples: Tangent and Collinear constraints that add nothing,
          Rectangular Pattern of components making nothing, Extrude OK doing nothing after
          an option change, and Fix/Unfix ignoring a mixed selection. Fusion nearly always
          explains a refusal. A one-line message in each of these places would save a lot of
          confusion.
     2. Work across components. Bugs 5–10 put new geometry in the clicked component
          instead of the active one. On top of that, Project (P) from another component projects
          nothing, and nested components can't be picked in the browser. The book's
          assemblies (Hot End, Pizza Cutter, Tesla Turbine, Space Prop Hilt) all depend on
          "project the previous part's face", so this pattern costs the most time.
     3. The Extrude Operation keeps changing. Choosing Symmetric flips Cut to Join, Flip
        leaves Join, a fin extrude came up as Cut, and a new component's first extrude
        defaults to Cut. Pressing Enter in the distance box commits the dialog, so the wrong
          operation goes through. The sign of a negative distance also isn't consistent (−8 grew
          into the body in one case).




                                                                                               Page 8 of 58
Fission 180 vs Fusion — Book Parity Report




     4. Sketches do things on their own. Snap is very strong: clicks 6–8 mm off the axis land
        on it. Lines near 45° get a driving 45° angle that makes the book's later Parallel
          constraint redundant. A dimension placed on top of another line becomes an angle
          constraint. Auto-projected face edges are on by default and come back after you
          delete them.
     5. Fillets and chamfers are refused as "too big". Sizes Fusion accepts are often refused
        or capped: 20 mm chamfer limited to 1.79 mm, 0.25" fillet at a tube joint, 0.25 mm
        chamfer on a patterned model, 4 mm silently capped to 3.99. Tapering two profiles
          also fails where Fusion tapers them as one.
     6. FreeCAD shows through. Examples: FreeCAD's modal "Constraint Substitution" pop-
        ups, internal construction geometry on ellipses and polygons, a spline control polygon,
        seam lines on round faces, and the SVG importer's own dialog. Others are two
          recovery dialogs after a crash, "+" and "…" buttons drawn as blank squares, and "&"
          vanishing from component names in buttons.
     7. Undo is unpredictable. One Ctrl+Z too many leaves the sketch, and Redo doesn't
          reopen it. Sometimes Undo takes two steps, sometimes it only removes constraints
          and leaves the lines. Undo can also hide the SKETCH tab, reset the units (bug 2) or
          leave an orphan step (bug 18). One drag + undo froze the app for about 80 s.
     8. Selecting things. Ctrl+click doesn't add to a sketch selection (Shift or plain click
        does), but the book says "hold Ctrl" many times. Offset-plane squares and the dialog's
        value boxes sit on top of faces and take the click. Small faces in a fitted view are hard
        to hit, and clicking a part of a subassembly selects the whole subassembly.
     9. Components. The first component isn't grounded automatically. A new component
        goes inside whatever component is active. Move rotates about the bounding-box
        centre, not the component origin.
   10. Inch designs are half metric. The sketch grid and snap stay metric. Model Parameters
       list mm, Thread defaults to ISO Metric, and tooltips say "Type a value (mm)".
   11. Data Panel and saving. New Folder has no inline name box, and folders have no Delete
       or Move. Save defaults to the project root, not the open folder.

  friction is in sketch behaviour (snap, auto-projection, selection), appearances, and small
  differences in the UI tour. Each entry below is one book step, labelled with the outcomes
  defined in the Summary.

  Test setup, limits and what could not be tested

  Setup
          Build: Fission 180 0.1.0-beta.3.3.9, the Linux AppImage release, on the FreeCAD 1.1.4
          core. No code was changed.
          Machine: a headless Linux sandbox with a virtual 1920×1200 display (Xvfb), software
          OpenGL, 2 CPU cores and 7.6 GB of RAM. That is slower than a normal PC, so the
          speed notes (the 25× knurl pattern that never finished, the ~60 s Hole, the ~80 s
          freeze after a drag + undo) should be rechecked on real hardware before they are
          treated as bugs.
          Input: every book step was done with real mouse and keyboard events sent through
          the display server, the same way a person would. Fission's own GUI-test harness was
          used only to read state (dialog fields, browser rows, timeline titles) and to confirm
          results such as volumes.
          One shortcut: because the Parameters "+" button is broken (bug 1), the user
          parameters for the Metric Bolt and the Drone were created by calling Fission's own
           parameters.add_user() , which is what "+" is meant to do. Everything after that was
          done through the UI.
