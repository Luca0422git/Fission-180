# Fission 180 for AI models

These documents are written for the AI models that use Fission 180's tools: through MCP (Claude
Desktop, Gemini CLI, Claude Code...), the chat panel inside Fission 180, or
`tools/fission180/fission180-cli`. Everything here is checked against the code: the tool pages
are generated from the tool catalogue, and every tool call shown in a document is run by
Fission 180's tests in real FreeCAD.

## Start here

1. [The handbook](fission180://docs/handbook.md): what Fission 180 is, how Fusion's ideas map to
   it (timeline, history marker, bodies, components, joints, sketches, parameters), units
   and coordinates, ids, how tool calls become undo steps, a good way to work.
2. [Sketches and profiles](fission180://docs/sketches.md) and
   [selectors](fission180://docs/selectors.md) (picking faces and edges, with a cookbook).
3. [Checking your work](fission180://docs/checking.md) and
   [troubleshooting](fission180://docs/troubleshooting.md) (failures and how to recover).
4. [Recipes](fission180://docs/recipes/index.md): common parts built step by step (bracket,
   enclosure with lid, shaft with keyway, gear pair, flange with bolt pattern, threaded
   fastener, snap-fit, sheet-like part, revolved knob, lofted handle, surface patch,
   parametric plate).

## Reference

- [All tools](fission180://docs/tools.md) with their Fusion commands, and the shared rules
  (selectors, picks, sketch planes, curves, ids, expressions).
- `reference/<tool>.md`, one page per tool: every argument with its type, unit, default and
  limits, the answer, the errors, and a complete example with its real answer
  ([extrude](fission180://docs/reference/extrude.md), [fillet](fission180://docs/reference/fillet.md),
  [inspect_design](fission180://docs/reference/inspect_design.md)...).
- [The golden models by feature](fission180://docs/examples/golden-models.md): about 450 small
  designs with measured results; read one with `docs_read` `golden/<id>`.
- `user/`: Fission 180's documentation for people, copied here so you can read everything the
  person can: [the cheat sheet](fission180://docs/user/cheat-sheet.md),
  [known issues](fission180://docs/user/known-issues.md),
  [the feature outline](fission180://docs/user/feature-outline.md) and the Fusion parity spec of
  every feature (`user/parity/<feature>.md`, for example
  [fillet](fission180://docs/user/parity/fillet.md)).

## Finding things

- `docs_search` ranks every section of every document by the words you give (BM25) and
  answers snippets with addresses (`path#anchor`); `docs_read` reads a document or one
  section, in pages; `examples_search` finds recipes and golden models by words, tool, op or
  tag. The MCP server answers these three itself, so they work even while Fission 180 is closed.
- Over MCP every document is a resource `fission180://docs/<path>` (add `#anchor` for one
  section); [fission180://docs/index](fission180://docs/index) lists them;
  [fission180://handbook](fission180://handbook) is all of them in one file (and
  [fission180://handbook/full](fission180://handbook/full) with the `user/` copies). The open
  design is [fission180://design](fission180://design).
- The same single file is written by `fission180-cli docs export FILE`, by
  `tools/fission180/make_ai_docs.py --export FILE`, and by Fission 180's **Add an AI app** dialog
  (**Save AI handbook...**), for AI apps that load files (Claude Desktop projects and the
  like). The dialog writes the compact file (about 45 thousand tokens, without the tool
  pages) to load, and next to it the one with every tool's page (about 170 thousand tokens).

## Checking your own work

Build one step at a time and check each step with numbers before trusting a picture:
[inspect_design](fission180://docs/reference/inspect_design.md) (every body, step and parameter, with a
snapshot id), [diff_design](fission180://docs/reference/diff_design.md) (what changed since that snapshot,
since `last_change` or since a step), [query_geometry](fission180://docs/reference/query_geometry.md) (the
faces and edges a selector picks, each with a `ref` selector that picks exactly that one),
[check_design](fission180://docs/reference/check_design.md) (valid solids, failed steps, overlapping bodies)
and [render](fission180://docs/reference/render.md) (a picture, with `highlight` to mark what a selector
picks).

## For Fission 180's developers

Hand-written documents live in this folder (sub-folders are fine): each becomes
`fission180://docs/<path>` at once, in the source tree, an installed Fission 180 and the Claude
extension. `tools.md`, `reference/`, `examples/golden-models.md` and `user/` are generated by
`tools/fission180/make_ai_docs.py` (never edit them by hand). Tool calls in a
` ```json fission180-calls ` block are run by `Fission180Tests/headless/docs_runner.py`
(`run_tests.sh --only headless`); a unit test (`test_ai_docs_contract.py`) checks that every
`fission180://` link, anchor included, exists and that the generated files are current.
